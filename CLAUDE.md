# Sendpaper

Print-and-mail ordering for people and AI agents: postcards (4×6 $2.99, 6×9 $3.99) and letters ($4.99, ≤3 pages) to US addresses. Orders come in through the website, the REST API (`/v1`), or the MCP server (`/mcp`, used by Codex, Muse Code and Claude). Every order returns a Stripe Checkout link a human pays, so there are no API keys and agents can't spend money on their own. **Fulfilment runs through PostGrid**: Ryan reviews each paid order in `/admin` and clicks **Approve & send to print**. `src/fulfill.ts` creates the PostGrid job, and a status sync (every 15 min while awake, plus whenever an admin page is opened) moves the order printing → mailed. A person still approves every piece; that's the content moderation step.

Stack: Node 24 running TypeScript natively (no build step), Express 5, Postgres, Stripe, `@modelcontextprotocol/sdk` (stateless Streamable HTTP). Deployed with `render.yaml` to Render, *My Workspace* (ryan.j.tish@gmail.com), **not** the ryan@render.com work account. The Codex plugin, MCP registry `server.json` and Muse Code snippet live in a separate repo at `~/sendpaper-plugin`, **public at github.com/ryan-tish/sendpaper-plugin since 2026-10-02**. `codex plugin marketplace add ryan-tish/sendpaper-plugin` works. Its README and manifests were checked against OpenAI's official plugins; the HOL plugin-scanner could NOT be run here (no pipx/uvx, PyPI blocked).

## Design decisions
- **Order links (`/quick`, `src/quick.ts`)**, added 2026-10-02, are for agents that browse instead of calling tools (for example Muse without our connector). One URL carries every field. GET renders the exact preview plus one Pay button and **never creates an order** (link previews and crawlers fetch with GET). POST creates the order with idempotency key `quick-<nonce from the rendered page>`, then 303s to Stripe. Validation errors name the URL parameter to fix. The same parameters prefill `/send`. Every page's head points agents to `/llms.txt`, `/openapi.json` and `/mcp` (`ai-agent-instructions` meta, `service-desc` link). Docs: `guides/order-links.mdx`.
- **Agent payments use Stripe shared payment tokens (SPTs)**, added 2026-10-02. They're available through the MCP tool `pay_order` and `POST /v1/orders/:id/pay {shared_payment_token}`, implemented as `payWithSharedToken` in `payments.ts`. It looks up the grant (`GET /v1/shared_payment/granted_tokens/:id`, `Stripe-Version: 2026-04-22.preview`), checks it's active, in USD and at least the order price, then creates and confirms a PaymentIntent with `payment_method_data[shared_payment_granted_token]`. The idempotency key is `spt-pay-<order>-<token>`. Agents get tokens from Stripe Link (`npx @stripe/link-cli spend-request create --credential-type shared_payment_token --network-id <ours> --request-approval`). The site and docs now market this ("Your agent can pay. Safely."), and the FAQ promise changed from "a person pays" to "your agent pays only with your approval". The Checkout link remains the fallback. Seller docs: `stripe docs "/agentic-commerce/concepts/shared-payment-tokens?agent-seller=seller"`.
- **`/use-cases`** (`src/usecases.ts`, the `USE_CASES` array) is the single source for use cases. `docs/guides/use-cases.mdx` is GENERATED from it (see the node one-liner in git history); regenerate it rather than hand-editing. Caveats stay honest: we send First-Class only, with no certified mail.
- **Docs structure** (2026-10-02): Get started (what it is and who it's for, Quickstart), How-to guides (postcard, letter, agent payments, track and cancel, use cases), Connect your agent, Reference (tools, lifecycle, products, content policy, FAQ), and the API tab, which includes `POST /orders/{id}/pay`.
- **Visual design is "Meadow"** (Ryan chose it 2026-10-02 from three mockups; inspired by Mintlify and Cal.com): white space, one near-black primary button, green `#0F7A52` with lime `#8FD16A` accents, and Geist plus Geist Mono throughout. Tokens live in `layout.ts`, with a full dark-mode set. The airmail-stripe design it replaced is gone. **Setup instructions live only in the docs**: the homepage hero is text-only (the agent screenshot moved to a "See it in action" section below it, because the hero felt busy) and keeps one copyable command with a custom (non-native) agent dropdown, built as an accessible listbox, (Codex, Claude Code, Muse Code, Cursor, VS Code, any MCP client; the choice is remembered in localStorage) plus a link to that client's docs page, and `/agents` 301s to the docs quickstart. The homepage was deliberately trimmed on 2026-10-02 (Ryan: "less busy, more modern"), so the "Built to hand to an agent", "What happens after the tool call" and "Not using an agent?" sections were removed. Don't re-add them; that content lives in the docs. **Light mode is the default for everyone**; dark is opt-in via the nav toggle (`localStorage.theme`) and no longer follows the OS setting. The docs default to light too. Pricing cards share five identical rows (`DETAILS` in `landing.ts`: Size, Printing, Writing, Postage, Mailed) so they compare at a glance. **`/send` is `src/send.ts`**: a product picker, a photo (drag and drop) or text front with color swatches, character counters, and a sticky live preview that flips front and back, using the same `THEMES` colors as the print sheet.
- **Pay per order, no accounts.** The `checkout_url` is `/o/:id/pay`, which creates a fresh Stripe session on every visit, so links never expire.
- **A person reviews before printing.** This is the content moderation step (USPS rules plus vendor rules) and the reason the admin queue exists. Do not add automatic printing without an automated moderation pass.
- **The print preview is the print sheet.** `render.ts` produces the HTML for both, so the customer approves exactly what gets printed.
- **Return address is required**, so every piece can be traced if someone abuses the service.
- Lob's terms forbid resale without its Partner Program. Use PostGrid (which has a reseller program) or Stannp as the print backend.
- Competitors already exist (PostAgent, MailStream, mailsnail at $1–1.50, Letter IRL). We compete on being consumer-friendly and getting into the Codex and Muse channels first, not on price.

## Traps
- **Never put `\n`-style escapes in inline page scripts inside TS template literals.** It took two rounds to get right, and a broken escape turned into a raw line break that killed the whole `/send` script. Use `String.fromCharCode(10)` / `(92)`, and syntax-check served scripts (`node --check`) after any change.
- **Agent payments DON'T WORK YET in test or live**, because the restricted key lacks the permissions. It needs **PaymentIntents: Write**, **Shared Payment Tokens: Read**, and in test mode **Shared Payment Token Test Helpers: Write** (Stripe's error names each one). Live also needs `STRIPE_NETWORK_ID` (our Stripe business profile `profile_…`) set on Render, so `get_pricing` and `llms.txt` can tell agents what to scope tokens to. Until then, `pay_order` returns `payments_unavailable`.
- **Never return Stripe's raw error text to agents.** It includes our key prefix and account id. `stripeFailure()` in `payments.ts` passes through only card declines and token-not-found, and logs everything else.
- **PostGrid is in TEST mode on Render** (`POSTGRID_API_KEY=test_sk_…`): it produces PDF proofs and never mails. Switching to `live_sk_…` **prints and mails for real and costs money**; the admin panel shows a red "LIVE" pill when it does. Verified end to end on 2026-10-02 in test mode: a 4×6 text card, a 6×9 photo card and a 2-page letter were all accepted and the proofs looked right, and test "progressions" took an order to `mailed`. **The LIVE key works (2026-10-03)**: it's in `~/.sendpaper.env` as `POSTGRID_LIVE_KEY` but deliberately NOT on Render yet. Switch Render the same day Stripe goes live, or test-paid orders could be approved into real mail. The live API returns 403 `org_missing_payment_method_error` until a card is attached in PostGrid billing. The first real card (`postcard_wo9BzRRWrpihAmn17EBqZE`, 4×6, to Ryan) was sent directly through the API using `postcardHtml`, outside the order system, so it doesn't prove Stripe live or the admin flow. Its proof looked right. Whether it arrives is UNCONFIRMED, and the key was pasted in chat, so roll it after launch.
- **PostGrid auto-cancels content that overlaps its address areas** (`cancellation.reason = invalid_content`). It owns the RIGHT half of postcard backs and the top ~2.75in of letter page 1. `postcardHtml`/`letterHtml` in `fulfill.ts` respect this; don't move the message or remove the 2.35in letter spacer without re-proofing. PostGrid adds no letter margins (we set `@page`), and pages include a 0.125in bleed (6.25×4.25 / 9.25×6.25).
- **Uploaded photos must be reachable by PostGrid**: `/images/…` paths become absolute `BASE_URL` URLs, so a photo order sent from a local server will fail to render. Test photos with a public https URL.
- The customer-facing preview (`render.ts`) is close to, but not pixel-identical with, PostGrid's output (PostGrid prints its own address block, in caps after CASS). The PDF proof link in admin is the source of truth.
- **Long one-line commands in a grid column must have `grid-template-columns: minmax(0, 1fr)` on the grid and `min-width: 0` on the flex row.** Otherwise the grid track grows to the command's full width and runs under the neighbouring column (it hid the Copy button once).
- **Stripe holds API refunds for dashboard approval on this account.** `refunds.create` with the restricted key returns 403 and opens an approval request; retries return "already an approval request waiting". The admin "Reject & refund" button shows Stripe's reason and leaves the order unchanged. After Ryan approves in the dashboard, clicking the button again sees the existing refund via `refunds.list` and just records it. Refunds use the idempotency key `refund-<order id>`.
- **Never let an upstream error reach Express's default handler.** Stripe errors carry `statusCode` and `headers`, which Express forwards verbatim (we leaked Stripe's 403/400 and CSP headers once). The global error handler in `server.ts` now swallows them.
- **The GitHub account was renamed `ryan-fern` → `ryan-tish` (noticed 2026-10-01), and this repo is now PUBLIC** (it was created private; it went public around the time Mintlify was set up). Never commit secrets: keys live in Render's environment variables and `~/.sendpaper.env`. The full history was scanned clean on 2026-10-01.
- **Mintlify uses `"icons": {"library": "lucide"}`**, so card icons must be Lucide names (`mail`, not Font Awesome's `envelope`). An unknown name renders no icon, with no error.
- **The Mintlify CLI refuses Node 25.** Run it under Node 22, pinned: `cd docs && npx -y -p node@22 -p mint@4.2.949 -- mint validate` (and `mint broken-links`, `mint dev`).
- **Keep one canonical copy of the docs.** Once `DOCS_URL` is set, the built-in `/docs` page redirects. Point Mintlify's custom domain at `docs.<our domain>`, never leave it on `*.mintlify.site` long-term (that subdomain accrues the search credit instead of us). Keep `/llms.txt` on the main domain, because agents look there first.
- **The docs must not claim registry listings or submissions that haven't happened.** Two premature claims were caught and removed on 2026-10-01.
- **Postgres was upgraded to basic-256mb on 2026-10-02**, so the free-tier expiry is gone. The web service was upgraded to a paid instance (`0.5c-512mb`) by Ryan in the dashboard on 2026-10-02, after the Render API returned 500 on `PATCH /services/:id {serviceDetails:{plan:"starter"}}`. Plan changes need the dashboard.
- **Imports must use the `.ts` extension**, and only erasable TypeScript syntax is allowed (no enums or namespaces), because Node strips types at runtime.
- The Stripe webhook route must stay **before** any JSON body parser in `server.ts`.
- The Render CLI default config is the WORK account. For personal deploys use `RENDER_CLI_CONFIG_PATH=~/.render/cli-personal.yaml`.
- `[hidden]` needs `display:none !important` in `layout.ts`. Without it, `fieldset{display:grid}` shows hidden sections.
- Local DB: a project-local cluster in `.pgdata` on port 54330 (`pg_ctl -D .pgdata -o "-p 54330 -k /tmp" start`).
