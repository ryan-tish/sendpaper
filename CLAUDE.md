# Sendpaper

Print-and-mail ordering for people and AI agents: postcards (4×6 $2.99, 6×9 $3.99) and letters ($4.99, ≤3 pages) to US addresses. Orders come in through the website, the REST API (`/v1`), or the MCP server (`/mcp`, used by Codex, Muse Code and Claude). Every order returns a Stripe Checkout link a human pays, so there are no API keys and agents can't spend money on their own. **Fulfilment runs through PostGrid**: Ryan reviews each paid order in `/admin` and clicks **Approve & send to print**. `src/fulfill.ts` creates the PostGrid job, and a status sync (every 15 min while awake, plus whenever an admin page is opened) moves the order printing → mailed. A person still approves every piece; that's the content moderation step.

Stack: Node 24 running TypeScript natively (no build step), Express 5, Postgres, Stripe, `@modelcontextprotocol/sdk` (stateless Streamable HTTP). Deployed with `render.yaml` to Render, *My Workspace* (ryan.j.tish@gmail.com), **not** the ryan@render.com work account. The Codex plugin, MCP registry `server.json` and Muse Code snippet live in a separate repo at `~/sendpaper-plugin`, **public at github.com/ryan-tish/sendpaper-plugin since 2026-10-02**. `codex plugin marketplace add ryan-tish/sendpaper-plugin` works. Its README and manifests were checked against OpenAI's official plugins; the HOL plugin-scanner can't be installed locally (PyPI blocked), so it runs as SHA-pinned GitHub Actions CI in the plugin repo (`.github/workflows/hol-plugin-scanner.yml`; passes the 80/130 gate, findings in the repo's code-scanning alerts; only a screenshots `note` remains). ## Design decisions
- **Order links (`/quick`, `src/quick.ts`)**, added 2026-10-02, are for agents that browse instead of calling tools (for example Muse without our connector). One URL carries every field. GET renders the exact preview plus one Pay button and **never creates an order** (link previews and crawlers fetch with GET). POST creates the order with idempotency key `quick-<nonce from the rendered page>`, then 303s to Stripe. Validation errors name the URL parameter to fix. The same parameters prefill `/send`. Every page's head points agents to `/llms.txt`, `/openapi.json` and `/mcp` (`ai-agent-instructions` meta, `service-desc` link). Docs: `guides/order-links.mdx`.
- **Agent payments use Stripe shared payment tokens (SPTs)**, added 2026-10-02. They're available through the MCP tool `pay_order` and `POST /v1/orders/:id/pay {shared_payment_token}`, implemented as `payWithSharedToken` in `payments.ts`. It looks up the grant (`GET /v1/shared_payment/granted_tokens/:id`, `Stripe-Version: 2026-04-22.preview`), checks it's active, in USD and at least the order price, then creates and confirms a PaymentIntent with `payment_method_data[shared_payment_granted_token]`. The idempotency key is `spt-pay-<order>-<token>`. Agents get tokens from Stripe Link (`npx @stripe/link-cli spend-request create --credential-type shared_payment_token --network-id <ours> --request-approval`). The site and docs now market this ("Your agent can pay. Safely."), and the FAQ promise changed from "a person pays" to "your agent pays only with your approval". The Checkout link remains the fallback. Seller docs: `stripe docs "/agentic-commerce/concepts/shared-payment-tokens?agent-seller=seller"`.

## Traps
